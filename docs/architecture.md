# معماری محتوا — کرین یدک

**نسخه ۱.۰ — ۱۹ شهریور ۱۴۰۵ (۲۰۲۶-۰۹-۱۰)**
وضعیت: پیش‌نویس، در انتظار تأیید کارفرما.

---

## چرا این سند وجود دارد

پروژه یک ماه در حلقه‌ی زیر گیر کرده بود:

> مشکل پیدا می‌شود ← یک دکمه یا فیلد اختصاصی ساخته می‌شود ← موقتاً حل
> می‌شود ← مشکل بعدی ← دکمه‌ی بعدی ← دکمه‌های قبلی فراموش و به آشغال
> تبدیل می‌شوند.

سنجش وضعیت در لحظه‌ی نوشتن این سند:

| شمارش | مقدار |
|---|---|
| سیستم محتوای هم‌زمانِ زنده برای یک کار | **۳** (`brandProfile`، `custom_sections`، `contentBlocks`) |
| دکمه‌ی «تعمیر/ورود/مهاجرت» در پنل | **۶** |
| گروه ACF | **۷** |

مکانیزم شکست، فراموشی نیست. این است:

> **افزودن رایگان است، حذف‌کردن هزینه و حافظه می‌خواهد. پس سیستم فقط
> بزرگ می‌شود.**

و هر افزوده، ناسازگاری تازه‌ای می‌سازد؛ ناسازگاری، «دکمه‌ی تعمیر» می‌خواهد؛
و دکمه‌ی تعمیر، خودش یک افزوده‌ی دیگر است. حلقه، خودتقویت‌شونده است.

این سند، قرارداد است. اگر کاری با آن در تضاد باشد، آن کار غلط است — نه سند.

## ۱. پالت بسته — دقیقاً هفت بلوک

هر محتوایی روی این سایت، روی **برند، محصول یا دسته**، از یکی از این هفت
بلوک ساخته می‌شود. نه بیشتر.

> «سری‌های دماگ» یک فیلد نیست. یک **جدول** است که کسی پرش کرده.
> این جمله، کل تغییر معماری است.

### ۱. متن — `text`

| | |
|---|---|
| **برای چه** | متن راهنما، معرفی، شرح فنی، هر نثری |
| **فیلدها** | `heading`، `body` (ویرایشگر غنی) |
| **رندر** | `prose-crane`، عرض ۷۰ کاراکتر برای خوانایی |
| **پردازش خودکار** | لینک‌دهی داخلی، پیچیدن جدول‌ها برای موبایل، تبدیل تصاویر به AVIF، افزودن `width/height` و `loading="lazy"` |
| **داده‌ی ساختاریافته** | ندارد (بخشی از `mainContentOfPage`) |

### ۲. جدول — `table`

| | |
|---|---|
| **برای چه** | هر مقایسه یا ماتریس: سری‌ها، مدل‌های سازگار، تفاوت نسل‌ها |
| **فیلدها** | `heading`، `intro`، `col1..col5`، `rows[c1..c5]` |
| **رندر** | جدول معنایی، ستون اول `<th scope="row">`، اسکرول افقی در موبایل |
| **قاعده‌ی مهم** | ستونی که در **همه‌ی** ردیف‌ها خالی است، اصلاً رندر نمی‌شود |

⚠️ سقف پنج ستون عمدی است. جدول شش‌ستونی روی موبایل فارسی خوانا نیست؛
اگر به ستون ششم نیاز داشتید، احتمالاً دو جدول لازم است.

### ۳. پرسش و پاسخ — `faq`

| | |
|---|---|
| **برای چه** | پرسش‌های واقعی خریدار |
| **فیلدها** | `heading`، `faqs[question, answer]` |
| **رندر** | `<details>` بومی — بدون جاوااسکریپت، همیشه قابل خواندن برای گوگل |
| **داده‌ی ساختاریافته** | `FAQPage` |

⚠️ فقط پرسش‌های **دارای پاسخ** وارد اسکیما می‌شوند. `FAQPage` با پاسخ
خالی، نقض راهنمای گوگل است و می‌تواند rich result کل صفحه را حذف کند.

### ۴. قطعات مرتبط — `parts`

| | |
|---|---|
| **برای چه** | قطعات پرتقاضای یک برند یا مکمل‌های یک محصول |
| **فیلدها** | `parts[part_name, category, failure_reason]` |
| **رندر** | کارت، با لینک به **مسیر واقعی دسته** |
| **چرا مهم است** | این باارزش‌ترین لینک داخلی سایت است: انتقال اعتبار از صفحه‌ی برند به سیلوی دسته |

⚠️ لینک به صفحه‌ی جستجو ممنوع — آن صفحه `noindex` است و هیچ اعتباری
منتقل نمی‌کند.

### ۵. رسانه — `media`

| | |
|---|---|
| **برای چه** | عکس محصول، نقشه‌ی فنی، ویدیو |
| **فیلدها** | `media[kind, asset, video_url, caption, alt_text]` |
| **رندر** | AVIF با fallback به WebP، `lazy`، ابعاد صریح |
| **ویدیو** | الگوی facade — پوستر + کلیک. هرگز `iframe` مستقیم |

⚠️ `iframe` یوتیوب/آپارات بیش از ۵۰۰ کیلوبایت و چند درخواست مسدودکننده
است. گوگل برای «داشتن ویدیو» رتبه نمی‌دهد ولی Core Web Vitals را
اندازه می‌گیرد.

### ۶. مشخصات فنی — `specs`  ← **جدید**

| | |
|---|---|
| **برای چه** | جفت‌های کلید/مقدار: ظرفیت، ولتاژ، کلاس کارکرد، ابعاد |
| **فیلدها** | `heading`، `specs[label, value, unit]` |
| **رندر** | `<dl>` — لیست تعریف، نه جدول |
| **داده‌ی ساختاریافته** | `additionalProperty` روی `Product` |

⚠️ **چرا جدول جایش را نمی‌گیرد:** جدول عمومی نمی‌داند کدام ستون «نام
مشخصه» و کدام «مقدار» است، پس نمی‌تواند `PropertyValue` تولید کند. این
تنها بلوکی است که وجودش را با *داده‌ی ساختاریافته* توجیه می‌کند، نه با
ظاهر.

### ۷. هشدار — `callout`  ← **جدید**

| | |
|---|---|
| **برای چه** | هشدار ایمنی، نکته‌ی نصب، تذکر سفارش |
| **فیلدها** | `tone` (خطر / نکته / توصیه)، `body` |
| **رندر** | جعبه‌ی رنگی با آیکون، متمایز از متن اطراف |
| **دسترسی‌پذیری** | `role="note"`؛ رنگ **هرگز** تنها حامل معنا نیست — برچسب متنی همیشه کنارش هست (WCAG 1.4.1) |

⚠️ در صنعت جرثقیل، هشدار ایمنی از نظر معنا با متن معمولی یکی نیست.
خواننده دنبالش می‌گردد و باید در یک نگاه پیدا شود.

### آنچه بلوک **نیست**

قالب صفحه، نه محتوا: هدر، فوتر، بردکرامب، ناوبری چسبان، فرم استعلام،
جعبه‌ی نویسنده، کارت محصول. این‌ها ساختار سایت‌اند و در کد می‌مانند.
مرز ساده است: **اگر مدیر محتوا باید بتواند حذفش کند، بلوک است.**

## ۲. قاعده‌ی تصمیم — برای هر درخواست تازه

| درخواست | بلوک |
|---|---|
| «باید بنویسیم چطور پلاک را بخوانند» | متن |
| «این برند ۶ سری دارد» | جدول |
| «مشخصات فنی این محصول» | مشخصات فنی |
| «مشتری‌ها این را می‌پرسند» | پرسش و پاسخ |
| «این قطعات را با هم می‌خرند» | قطعات مرتبط |
| «عکس نقشه‌ی انفجاری» | رسانه |
| «هشدار: بدون کد فنی سفارش ندهید» | هشدار |
| «این برند سری ندارد، به‌جایش X دارد» | **جدول** — و اگر جدول نیست، متن |

پرسش درست هرگز «چه فیلدی اضافه کنم؟» نیست. همیشه این است:

> **این محتوا کدام‌یک از هفت بلوک است؟**

## ۳. سه قاعده‌ی الزام‌آور

### قاعده‌ی ۱ — پالت بسته است

هیچ فیلد اختصاصیِ تازه برای هیچ برند، محصول یا دسته‌ای ساخته نمی‌شود.
هرگز.

تغییر پالت ممکن است، ولی **رویداد نادر و ثبت‌شده** است: نسخه‌ی این سند
بالا می‌رود، بلوک تازه با دلیلش اینجا مستند می‌شود، و آنچه جایگزینش
می‌کند در **همان تغییر** حذف می‌شود.

### قاعده‌ی ۲ — هر افزوده، حذفش را با خودش می‌آورد

اگر چیزی جایگزین چیز دیگری می‌شود، قدیمی در **همان کامیت** می‌میرد.

«بعداً پاکش می‌کنیم» و «می‌گذاریمش در backlog» ممنوع است. دقیقاً همین دو
جمله، سه سیستم هم‌زمان و شش دکمه‌ی تعمیر ساختند.

اگر حذف در همان تغییر ممکن نیست، تغییر آماده نیست.

### قاعده‌ی ۳ — build روی آشغال می‌شکند

قاعده‌ی ۱ و ۲ به حافظه‌ی من تکیه دارند و حافظه‌ی من ثابت کرده که قابل
اتکا نیست. تنها چیزی که در این پروژه واقعاً جلوی اشتباه را گرفته، تستی
بوده که شکسته است.

`scripts/check-architecture.mjs` در `npm run check` اجرا می‌شود و build را
می‌شکند اگر:

1. گروه ACFای خارج از فهرست مجاز وجود داشته باشد
2. گروه ACFای وجود داشته باشد که هیچ‌جای `src/` مصرفش نمی‌کند
3. `admin_post_` هندلری خارج از فهرست مجاز ثبت شده باشد
4. **نوع بلوکی در ACF تعریف شده باشد که `ContentBlocks.astro` رندرش نمی‌کند — یا برعکس**

مورد چهارم مهم‌ترین است: تضمین می‌کند پالت و رندرکننده هرگز از هم واگرا
نشوند.

## ۴. فهرست حذف

با تأیید این سند، این‌ها **پاک می‌شوند** — نه غیرفعال، نه کامنت، پاک.

### گروه‌ها و فیلدهای ACF

| مورد | جایگزین |
|---|---|
| `brandProfile` (۱۳ فیلد) | بلوک‌ها |
| ↳ `custom_sections` | بلوک متن |
| ↳ `series` | بلوک جدول |
| ↳ `common_parts` | بلوک قطعات مرتبط |
| ↳ `technologies` | بلوک جدول |
| ↳ `faqs` | بلوک پرسش و پاسخ |
| ↳ `media` | بلوک رسانه |
| `categoryContent` (۱۱ فیلد) | بلوک‌ها |
| `brand_section_order` | ترتیب ردیف‌های بلوک |

### فایل‌های فرانت‌اند

`BrandGuide.astro` · `CategoryGuide.astro` · `brand-profile.ts` ·
`brand-queries.mjs` · `brand-custom-sections.ts` · `section-order.ts` ·
`category-content.ts` · `check-brand-shapes.mjs` · `diagnose-brand.mjs`

### دکمه‌های پنل: از ۶ به ۱

| دکمه | سرنوشت | چرا |
|---|---|---|
| `cyh_hub_import` | **بازنویسی** → تنها ابزار باقی‌مانده | ورود انبوه ۱۹ برند و ۳۱ دسته واقعاً لازم است؛ ولی بلوک وارد می‌کند، نه فیلد اختصاصی |
| `cyh_hub_repair` | حذف | برای تعمیر HTML خرابِ گذشته بود؛ یک‌بار اجرا، بعد بی‌مصرف |
| `cyh_repair_slugs` | حذف پس از آخرین اجرا | مهاجرت یک‌باره |
| `cyh_build_hierarchy` | حذف پس از آخرین اجرا | مهاجرت یک‌باره |
| `cyh_blocks_migrate` | حذف پس از آخرین اجرا | مهاجرت یک‌باره |
| `cyh_import_submit` | حذف | نسخه‌ی قدیمی ورود محصول |

⚠️ سه مورد «مهاجرت یک‌باره» عمداً مهلت‌دار هستند. ابزار مهاجرتی که بعد از
مهاجرت بماند، همان فنجان یک‌بارمصرف است.

### گروه‌هایی که می‌مانند

`productFields` (هویت محصول: کد فنی، برند، دسته — نه محتوا) ·
`brandFields` (هویت برند: نام لاتین، لوگو) ·
`siteOptionsFields` (تنظیمات سایت) ·
`authorProfile` (E-E-A-T) ·
`contentBlocks` (تمام محتوا)

مرز روشن است: **هویت و پیکربندی در فیلد می‌ماند؛ محتوا در بلوک می‌رود.**

## ۵. ترتیب اجرا

| فاز | کار | معیار «تمام شد» |
|---|---|---|
| ۱ | افزودن بلوک `specs` و `callout`؛ اتصال پالت به محصول و دسته | هر سه نوع موجودیت از یک مدل استفاده می‌کنند |
| ۲ | مهاجرت داده‌ی موجود، سپس **حذف** فهرست بالا | `grep` هیچ ارجاعی به سیستم‌های قدیمی پیدا نکند |
| ۳ | `check-architecture.mjs` + همین سند | `npm run check` روی آشغالِ ساختگی می‌شکند |
| ۴ | **کارفرما محتوای واقعی را وارد می‌کند** | — |

هیچ فیچر تازه‌ای تا پایان فاز ۳. نه صفحات حقوقی، نه جستجوی کد فنی،
هیچ‌چیز.
