# راهنمای گام‌به‌گام نصب بک‌اند روی cPanel (برای کسی که تازه‌کار بک‌اند است)

شما الان یک وردپرس خام + ACF Pro + WPGraphQL نصب کرده‌اید. این سه‌تا به
تنهایی هنوز «محصول»، «برند» یا هیچ ساختار مخصوص کرین یدک را نمی‌شناسند —
پلاگین `crane-yadak-headless.zip` دقیقاً همان چیزی است که این ساختارها
را به وردپرس شما اضافه می‌کند. این راهنما مرحله‌به‌مرحله شما را از صفر تا
جایی می‌برد که بتوانیم فرانت‌اند را به دیتای واقعی وصل کنیم.

هیچ‌کدام از این مراحل نیاز به خط فرمان (Terminal/SSH) یا دانش برنامه‌نویسی
ندارد — همه از طریق پنل وردپرس (wp-admin) انجام می‌شود.

---

## مرحله ۱: نصب پلاگین `crane-yadak-headless`

ساده‌ترین راه، از خودِ پنل وردپرس است (نیازی به File Manager سی‌پنل
نیست):

1. وارد پنل وردپرس شوید: `https://دامنه‌شما/wp-admin`
2. از منوی سمت راست: **افزونه‌ها (Plugins) ← افزودن افزونه جدید (Add
   New)**
3. بالای صفحه دکمه‌ی **بارگذاری افزونه (Upload Plugin)** را بزنید.
4. فایل `crane-yadak-headless.zip` را انتخاب و **نصب کن (Install Now)**
   را بزنید.
5. بعد از اتمام نصب، دکمه‌ی **فعال‌سازی افزونه (Activate Plugin)** را
   بزنید.

اگر با پیام خطای «فایل قابل بارگذاری نیست» مواجه شدید (نادر، ولی روی
بعضی هاست‌های اشتراکی به‌خاطر محدودیت حجم آپلود پیش می‌آید)، به‌جای این
مرحله می‌توانید از **File Manager** سی‌پنل استفاده کنید: فایل zip را در
مسیر `public_html/wp-content/plugins/` آپلود کرده و Extract کنید، سپس
دوباره به مرحله‌ی «فعال‌سازی» در پنل وردپرس برگردید.

**نکته‌ی مهم:** بعد از فعال‌سازی، اگر پیام هشدار قرمزی دیدید که می‌گوید
افزونه‌های پیش‌نیاز فعال نیستند، یعنی ACF Pro یا WPGraphQL شما به هر
دلیلی غیرفعال شده — از منوی «افزونه‌ها» بررسی کنید هر دو فعال (Active)
باشند.

---

## مرحله ۲: یک کلیک حیاتی و فراموش‌نشدنی — ذخیره‌ی Permalinks

این پلاگین چند مسیر جدید (مثل `/brands/`) به وردپرس اضافه می‌کند، اما
وردپرس این مسیرهای جدید را تا یک بار «ذخیره‌ی دستی» تنظیمات لینک‌ها
نمی‌شناسد. این یک باگ کلاسیک وردپرسی است که هرکسی احتمال دارد فراموش
کند، پس آن را همین الان انجام دهید:

1. از منو: **تنظیمات (Settings) ← پیوندهای یکتا (Permalinks)**
2. بدون تغییر هیچ گزینه‌ای، فقط دکمه‌ی **ذخیره تغییرات (Save Changes)**
   را بزنید.

---

## مرحله ۳: تنظیمات خودِ پلاگین (ایمیل + دامنه‌های مجاز)

1. از منو: **تنظیمات (Settings) ← کرین یدک Headless**
2. در «ایمیل دریافت درخواست‌های استعلام» ایمیلی که می‌خواهید لیدهای فرم
   تماس به آن ارسال شود را وارد کنید (یا خالی بگذارید تا از ایمیل مدیر
   سایت استفاده شود).
3. در «دامنه‌های مجاز (CORS)»، آدرس فرانت‌اندی که قرار است به این
   وردپرس درخواست بزند را وارد کنید. چون فرانت‌اند شما هنوز روی دامنه‌ی
   نهایی منتشر نشده، فعلاً همین‌قدر کافی است:
   ```
   http://localhost:4321
   ```
   (بعداً وقتی دامنه‌ی نهایی فرانت‌اند مشخص شد، همین‌جا یک خط دیگر با آن
   دامنه اضافه می‌کنیم — این تنظیم را در ذهن نگه دارید، در پیام بعدی که
   با هم فرانت‌اند را وصل می‌کنیم لازم می‌شود.)
4. در همین صفحه، دو بخش تنظیمات دیگر هم می‌بینید که فعلاً می‌توانید
   نادیده بگیرید:
   - **«پشت CDN/پراکسی معتمد هستم (مثل کلودفلر)»** — فقط اگر بعداً
     وردپرس شما پشت کلودفلر یا CDN مشابه قرار گرفت لازم می‌شود. برای
     اکثر هاست‌های اشتراکی cPanel (مثل الان شما) باید **غیرفعال** بماند.
   - **«انتشار خودکار سایت (Auto-Deploy)»** — این را در **مرحله‌ی ۷**
     همین راهنما کامل توضیح می‌دهیم؛ چون نیاز به فرانت‌اند منتشرشده دارد
     که هنوز به آن نرسیده‌ایم، فعلاً خالی بگذارید.
5. **ذخیره تنظیمات** را بزنید.

---

## مرحله ۴: بررسی این‌که منوهای جدید ظاهر شده‌اند

بعد از فعال‌سازی، در ستون سمت راست پنل وردپرس باید این آیتم‌های جدید را
ببینید (هرکدام یک آیکون مخصوص به خود دارند):

- **محصولات** (آچار 🔧)
- **برندها** (ستاره ⭐)
- **صنایع تحت پوشش** (ساختمان 🏢)
- **اسناد فنی** (سند 📄)
- **درخواست‌های استعلام** (پاکت ✉️ — اینجا لیدهای فرم تماس ذخیره
  می‌شوند)
- **تنظیمات کرین یدک** (زیر منوی تنظیمات ACF — برای FAQ/ساعات کاری)

اگر همه‌ی این‌ها را می‌بینید، یعنی مرحله‌ی ۱ درست انجام شده. اگر یکی
غایب است، به من بگویید کدام‌یک — احتمالاً یک قدم بالاتر مشکلی پیش آمده.

---

## مرحله ۵: تست این‌که WPGraphQL این ساختار جدید را می‌شناسد

این مهم‌ترین مرحله‌ی تایید است — بدون این تست، نمی‌دانیم WPGraphQL و ACF
واقعاً با هم صحبت می‌کنند یا نه.

1. از منوی سمت راست پنل وردپرس، دنبال آیتمی به اسم **GraphQL** بگردید
   (این منو از خودِ افزونه‌ی WPGraphQL می‌آید، نه از پلاگین من) و روی
   **GraphiQL IDE** کلیک کنید.
2. یک صفحه‌ی دو ستونه باز می‌شود (سمت چپ جای نوشتن Query، سمت راست جای
   دیدن نتیجه).
3. در ستون چپ این متن را دقیقاً کپی/پیست کنید:

   ```graphql
   query TestConnection {
     craneBrands {
       nodes {
         title
       }
     }
   }
   ```

4. دکمه‌ی Play (▶) بالای صفحه را بزنید.

**نتیجه‌ی موفق** چیزی شبیه این است (چون هنوز هیچ برندی وارد نکرده‌اید،
آرایه خالی است، ولی هیچ خطایی نباید باشد):

```json
{
  "data": {
    "craneBrands": {
      "nodes": []
    }
  }
}
```

اگر این را دیدید، یعنی همه‌چیز درست وصل است 🎉 — به من بگویید «تست
موفق بود» و برویم سراغ مرحله‌ی بعد.

**اگر خطا دیدید** (مثلاً `Cannot query field "craneBrands"`)، معمولاً
یکی از این دو دلیل است:
- نسخه‌ی ACF Pro شما قدیمی‌تر از نسخه‌ای است که پشتیبانی Native از
  GraphQL دارد؛ راه‌حل: افزونه‌ی رایگان **WPGraphQL for Advanced Custom
  Fields** را هم از افزونه‌ها › افزودن جدید نصب و فعال کنید، سپس دوباره
  تست کنید.
- پلاگین درست فعال نشده یا Permalinks ذخیره نشده (برگردید به مرحله‌ی
  ۱-۲).

فقط عین متن خطا را برای من کپی کنید، بدون این‌که نگران معنایش باشید —
من از روی متن خطا دقیقاً می‌گویم مشکل کجاست.

---

## مرحله ۶: وارد کردن یک برند و یک محصول آزمایشی

برای این‌که مطمئن شویم فیلدهای ACF هم درست کار می‌کنند:

1. از منو: **برندها ← افزودن برند جدید**
2. عنوان (Title) را بگذارید: `دماگ`
3. پایین صفحه، فیلدهای ACF («Brand Fields») را می‌بینید — `نام
   انگلیسی برند` را بگذارید `DEMAG` و بقیه را دلخواه پر کنید یا خالی
   بگذارید.
4. **انتشار (Publish)** را بزنید.
5. دوباره به GraphiQL IDE برگردید و همان Query مرحله‌ی ۵ را دوباره اجرا
   کنید. این بار باید ببینید:
   ```json
   { "data": { "craneBrands": { "nodes": [ { "title": "دماگ" } ] } } }
   ```

اگر این را دیدید، یعنی مسیر کامل — از فرم وردپرس تا خروجی GraphQL —
سالم است.

---

## مرحله ۷ (فعلاً اختیاری — فقط بخوانید): آشنایی با «انتشار خودکار» (Auto-Deploy)

این بخش را الان فقط بخوانید تا بدانید بعداً چه کاری در انتظارتان است؛
پرکردنش نیاز به یک فرانت‌اند واقعاً منتشرشده دارد که هنوز به آن
نرسیده‌ایم — می‌توانید همین الان رد شوید و به مرحله‌ی بعد بروید.

**چرا این ویژگی لازم است؟** فرانت‌اند سایت شما (Astro) یک سایت
«استاتیک» می‌سازد — یعنی وقتی شما (یا هرکسی در تیمتان که هیچ دانش
کدنویسی ندارد) در وردپرس یک محصول جدید منتشر یا ویرایش می‌کنید، آن
تغییر فوراً در وردپرس ذخیره می‌شود اما **در سایت زنده نمایش داده
نمی‌شود**، مگر این‌که فرانت‌اند دوباره Build و منتشر شود. این ویژگی
همان کاری است که در سوال شما مطرح شد: «مشتری نهایی باید بدون دانش
کدنویسی بتواند محصول/کاتالوگ/عکس اضافه کند».

**راه‌حل، وقتی به آن مرحله رسیدیم:**

1. یک حساب رایگان روی **Cloudflare Pages** (یا Netlify) برای فرانت‌اند
   می‌سازیم.
2. از تنظیمات آن سرویس، یک **Deploy Hook URL** می‌گیریم — آدرسی که با
   یک درخواست ساده، کل فرآیند build و انتشار را از راه دور فعال می‌کند.
3. برمی‌گردیم به همین صفحه‌ی تنظیمات پلاگین (تنظیمات ← کرین یدک
   Headless، همان‌جای مرحله‌ی ۳)، تیک «انتشار خودکار سایت» را فعال
   می‌کنیم و آن آدرس را در فیلد «آدرس Deploy Hook» وارد می‌کنیم.

از آن لحظه به بعد، هر بار که شما یا تیمتان یک محصول، برند، صنعت، سند
فنی یا مقاله را منتشر کنید، ظرف ۱ تا ۲ دقیقه سایت زنده خودش به‌روز
می‌شود — کاملاً خودکار، بدون نیاز به پیام‌دادن به من یا هر برنامه‌نویس
دیگری. اگر چند تغییر را پشت‌سرهم انجام دهید، سیستم آن‌ها را در یک
انتشار واحد جمع می‌کند (نه یک‌بار به‌ازای هر تغییر).

در همان صفحه یک دکمه‌ی **«همین حالا دیپلوی کن»** هم هست، برای وقتی که
می‌خواهید بدون ویرایش هیچ محتوایی، سایت را فوراً دوباره منتشر کنید.
صفحه‌ی تنظیمات همچنین نشان می‌دهد آخرین تلاش برای دیپلوی چه زمانی بوده
و موفق بوده یا نه.

⚠️ **آدرس Deploy Hook را محرمانه نگه دارید** — هرکسی که آن را داشته
باشد می‌تواند دیپلوی سایت شما را فعال کند، پس آن را در چت یا ایمیل باز
به اشتراک نگذارید.

## مرحله ۸: اطلاعاتی که در پیام بعدی از شما می‌خواهم

وقتی مراحل بالا را انجام دادید (مرحله‌ی ۷ را می‌توانید فعلاً رد کنید)،
این دو مورد را برای من بفرستید تا فرانت‌اند را به دیتای واقعی وصل کنم:

1. **آدرس دامنه‌ی وردپرس شما** (همان چیزی که در مرورگر برای ورود به
   wp-admin استفاده می‌کنید، مثلاً `https://admin.craneyadak.com` یا یک
   دامنه‌ی موقت سی‌پنل).
2. **نتیجه‌ی مرحله‌ی ۵** — «موفق بود» یا متن خطا.

با این دو مورد، در پیام بعدی مسیر GraphQL Endpoint دقیق شما را تایید
می‌کنم، متغیر محیطی فرانت‌اند (`PUBLIC_WP_API_URL` در فایل `.env`) را
برای شما مقداردهی می‌کنم، و شروع می‌کنیم به وصل‌کردن صفحات دسته‌بندی،
برندها و صنایع به دیتای واقعی به‌جای دیتای Mock فعلی.

(اگر مرحله‌ی ۷ را هم انجام دادید و Deploy Hook را وصل کردید، عالی؛ از
این به بعد دیگر لازم نیست برای هر تغییر محتوا به من پیام بدهید — سایت
خودش خودش را به‌روز نگه می‌دارد.)

## این پلاگین دقیقاً چه کاری می‌کند؟ (خلاصه‌ی مفهومی)

اگر کنجکاوید بدانید در پس‌زمینه چه اتفاقی افتاد:

- به وردپرس یاد داد چهار «نوع محتوای سفارشی» جدید بشناسد: محصول، برند،
  صنعت، سند فنی — این‌ها معادل همان آرایه‌های Mock در فرانت‌اند
  (`src/data/site.ts` و `content.ts`) هستند، فقط حالا واقعی و
  قابل‌ویرایش از پنل‌اند.
- به هرکدام «فیلدهای ACF» اضافه کرد (مثل کد فنی محصول، برند مرتبط،
  گالری تصاویر) — دقیقاً همان اطلاعاتی که فرانت‌اند برای نمایش صفحه‌ی
  محصول لازم دارد.
- یک «درِ خروجی» به اسم GraphQL باز کرد تا فرانت‌اند Astro بتواند این
  اطلاعات را از راه دور بخواند — این همان چیزی است که در مرحله‌ی ۵ تست
  کردیم.
- یک «درِ ورودی» هم برای فرم تماس ساخت (`/wp-json/crane/v1/inquiry`)
  تا وقتی مشتری فرم استعلام قیمت را در سایت پر می‌کند، این پیام واقعاً
  به وردپرس شما برسد و ذخیره/ایمیل شود.
