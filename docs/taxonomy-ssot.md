# ساختار دسته‌بندی — وردپرس مرجع است

## خلاصه‌ی تغییر

پیش از این، ساختار ۷ سیلو و ۳۱ دسته دستی در `src/data/taxonomy.ts` نوشته شده بود.
مدیر سایت نمی‌توانست دسته بسازد. حالا وردپرس مرجع است.

| | قبل | بعد |
|---|---|---|
| منبع ساختار | فایل کد | وردپرس |
| افزودن دسته | نیازمند برنامه‌نویس | از پنل، بدون کد |
| سیلوها در وردپرس | متن داخل فیلد توضیح | ترم والد واقعی |
| کشوی «دستهٔ مادر» | ۳۱ دسته‌ی برگ (بی‌معنا) | ۷ سیلو |

---

## نصب — یک‌بار

### ۱. افزونه

پنل وردپرس ← **افزونه‌ها ← افزودن ← بارگذاری افزونه**
فایل: `wordpress-plugin/crane-yadak-headless-1.4.0.zip`

اگر نسخه‌ی قبلی نصب است، اول آن را **غیرفعال و حذف** کنید. حذف افزونه هیچ داده‌ای
را پاک نمی‌کند — محصولات، دسته‌ها و مقادیر ACF در پایگاه داده می‌مانند.

### ۲. ساخت سلسله‌مراتب

پنل ← **محصولات کرین یدک ← ساختار دسته‌بندی** ← دکمه‌ی **«ساخت ۷ سیلو و مرتب‌سازی ۳۱ دسته»**

این دکمه سه کار می‌کند:

1. ۷ سیلو را به‌عنوان **دستهٔ مادر واقعی** می‌سازد
2. هر ۳۱ دسته را زیر والد درستش می‌برد
3. عبارت کلیدی، توضیح، آیکون و مترادف هر دسته را از ساختار قبلی منتقل می‌کند

> بدون قدم ۳، هر ۳۱ صفحه‌ی دسته `<title>` و `<h1>` خود را از دست می‌داد.
> اجرای دوباره‌ی این دکمه بی‌خطر است و چیزی را که خودتان نوشته‌اید بازنویسی نمی‌کند.

پس از اجرا، جدول همان صفحه باید درخت دوسطحی را نشان دهد: ۷ ریشه، هرکدام با فرزندانش.

### ۳. build

```bash
npm run build
```

انتظار:

```
✅ [taxonomy] 7 سیلو و 31 دسته از وردپرس خوانده شد.
```

## افزودن دسته‌ی جدید — از این پس

پنل ← **محصولات کرین یدک ← دسته‌بندی قطعات**

| فیلد | مقدار | اجباری |
|---|---|---|
| **نام** | نام فارسی، مثلاً `کوپلینگ جرثقیل سقفی` | بله |
| **نامک** | **لاتین**، مثلاً `crane-coupling` | بله |
| **دستهٔ مادر** | یکی از ۷ سیلو | بله |
| **توضیح** | یک جمله؛ زیر کارت دسته دیده می‌شود | خیر |
| **عبارت کلیدی** | عبارتی که باید برایش رتبه بگیرد | خیر |
| **نام‌های دیگر** | هر مترادف در یک خط؛ فقط برای جستجوی داخلی | خیر |
| **مسیر آیکون SVG** | فنی — خالی بگذارید، آیکون پیش‌فرض می‌آید | خیر |

سپس:

```bash
npm run build
```

آدرس صفحه به‌صورت خودکار ساخته می‌شود:

```
/categories/[نامکِ سیلو]/[نامکِ دسته]
```

**هیچ کدی لازم نیست.**

### نامک را خالی نگذارید

اگر خالی بماند، وردپرس از نام فارسی اسلاگ می‌سازد و نتیجه این است:

```
/categories/hoist-accessories/%DA%A9%D9%88%D9%BE%D9%84%DB%8C%D9%86%DA%AF
```

افزونه جلوی این را می‌گیرد و به‌جایش یک نامک موقت (`category-42`) می‌گذارد و
در بالای فهرست دسته‌ها هشدار می‌دهد. ولی نامک درست را باید خودتان بنویسید.

## سیلوی جدید

همان مسیر، فقط **دستهٔ مادر** را `هیچ‌کدام` بگذارید. هر ترم بدون والد، یک سیلو است.
هیچ فهرستی در کد وجود ندارد که لازم باشد به‌روز شود — این با تست پوشش داده شده
(`8th silo recognised with no code change`).

## ساختار دقیقاً دو سطح است

```
سیلو                    /categories/brake
└── دسته                /categories/brake/rectifier
    └── ❌ سطح سوم       پشتیبانی نمی‌شود
```

اگر دسته‌ای در سطح سوم بسازید، `npm run build` با پیام روشن متوقف می‌شود و
دقیقاً می‌گوید کدام دسته و چه باید کرد.

---

## ⚠️ تنها هزینه‌ی واقعی این معماری

**تغییر «دستهٔ مادر» یک دسته، آدرس آن را عوض می‌کند.**

```
/categories/hoist-accessories/crane-coupling
                ↓ تغییر والد به «محرکه ها»
/categories/drive-units/crane-coupling        ← آدرس قبلی ۴۰۴ می‌شود
```

تا وقتی سایت روی `localhost` است این بی‌اهمیت است — گوگل هیچ صفحه‌ای را ندیده.
**پس از انتشار**، هر تغییر والد به یک ریدایرکت ۳۰۱ نیاز دارد.

برای اینکه این اتفاق بی‌سروصدا نیفتد، `npm run build` هر تغییر آدرس را گزارش می‌دهد:

```
🔴 [taxonomy] 1 آدرس حذف یا جابه‌جا شد:
     /categories/hoist-accessories/crane-coupling
```

فهرست کامل آدرس‌ها هم در بالای `src/data/taxonomy.generated.ts` نوشته می‌شود،
پس هر تغییر ساختار در diff گیت دیده می‌شود.

---

## دو نکته‌ی فنی

**`src/data/taxonomy.generated.ts` را دستی ویرایش نکنید.** این فایل کشِ build است
و در هر `npm run build` از نو از وردپرس ساخته می‌شود. در گیت کامیت می‌شود تا
(الف) بدون دسترسی به وردپرس هم بشود build گرفت و (ب) تغییر آدرس‌ها در diff دیده شود.

**اگر وردپرس بالا نباشد،** `npm run build` با پیام روشن متوقف می‌شود. این عمدی است:
انتشار سایتی که همه‌ی صفحات دسته‌اش غایب است، بدتر از شکست build است.
`npm run dev` برعکس، با آخرین ساختار ذخیره‌شده ادامه می‌دهد.
