# سیستم محتوا — از فایل تا سایت، بی کپی/پیست

وضعیت (۲۸ آبان ۱۴۰۵): **هر چهار مرحله ساخته و آزموده شد** (کامپایلر، بازبین، اندپوینت افزونه‌ی ۳.۳۰.۰ + اسکریپت انتشار، workflow «Content»). روی سایت زنده هنوز اجرا نشده — منتظر نصب افزونه، Sync گروه ACF و سه secret.

## چرا

کارفرما: «کپی/پیست کند است؛ سیستمی هوشمند، توسعه‌پذیر و قابل‌اعتماد برای هر نوع محتوا — محصول، دسته، برند، مقاله».
تا امروز: متن به‌صورت HTML خام برای چسباندن در ویرایشگر تحویل می‌شد (متن SAGA1-L12) و پالت «بلوک‌های محتوا» که برای همین ساخته
شده بود کنار می‌ماند — بی FAQ ساختاریافته، بی ناوبری بخش‌ها، بی سبک یکسان. ابزار ورود JSON افزونه
(`class-content-import-hub.php`) وجود داشت ولی نوشتن JSON دستی برای انسان سخت است و تصاویر باید جدا بارگذاری می‌شدند.

## مسیر

```
content/<نوع>/<اسلاگ>/index.md  +  images/*.jpg
        │
        ▼  npm run content -- lint        (scripts/content/lint.mjs — خطا = توقف)
        ▼  npm run content -- build       (scripts/content/compile.mjs → .astro/content-out/<نوع>-<اسلاگ>.json)
        ▼  npm run content -- publish     (scripts/content/publish.mjs — dry-run؛ --apply --create --force)
        ▼  workflow «Content»             (.github/workflows/content.yml — push به content/ ← وردپرس ← Deploy)
```

`npm run check` همه‌ی فایل‌های `content/` را هر بار می‌سنجد؛ فایل خراب کامیت نمی‌شود.

## قالب فایل

```markdown
---
kind: product | category | brand | article
slug: saga-saga1-l12
intent: transactional | informational | commercial | navigational
title: …                       # H1 و عنوان صفحه؛ با « | کرین یدک» ≤ ۶۰ نویسه
primaryKeyword: …              # یکتا در کل مخزن — نگهبان هم‌نوع‌خواری
secondaryKeywords: [ … ]
excerpt: …                     # توضیح متا، ۷۰ تا ۱۵۸ نویسه
sources: [ { title, url } ]    # الزامی برای محصول و مقاله (قاعده‌ی ۲)
# فقط محصول: sku، brand، categories، gallery [{file, alt}]، specs [{label, value}]
---
متن مقدمه (کلیدواژه‌ی اصلی در ۱۰۰ واژه‌ی اول)

## عنوان بخش {nav="برچسب کوتاه"}
متن، جدول Markdown، ![alt](images/x.jpg "زیرنویس")، [لینک داخلی](/products/x/)

:::callout tip|note|warning|danger|info عنوان کادر
…
:::

## پرسش‌های متداول
:::faq
### پرسش؟
پاسخ
:::

## ویدیو
:::video url="https://www.aparat.com/v/…" alt="…"
```

هر `##` یک بلوک سایت است (همان پالت ACF، همان سبک برای همه‌ی محتوا). جدول‌ها کلاس `cy-compare` می‌گیرند، تصاویر `<figure>` با
ابعاد واقعی (بدون CLS) و در سایت AVIF می‌شوند.

## بازبین (lint) — چه چیزی انتشار را متوقف می‌کند

| قاعده | منبع |
|---|---|
| کلیدواژه‌ی اصلی در title و ۱۰۰ واژه‌ی اول | سئو |
| **هم‌نوع‌خواری:** یک کلیدواژه‌ی اصلی = یک صفحه (یکسان‌سازی ی/ک/نیم‌فاصله/رقم) | خواسته‌ی کارفرما |
| `intent` الزامی | تفکیک صفحه‌ی خرید از مقاله‌ی آموزشی |
| excerpt ≤ ۱۵۸ | `src/lib/seo-meta.ts` |
| H1 در متن ممنوع؛ عنوان تکراری ممنوع | سئو |
| هر تصویر alt واقعی (نه نام فایل)، فایل موجود، jpg/png/webp/avif | سئو، دسترس‌پذیری |
| دست‌کم یک تصویر، جدول یا ویدیو | خواسته‌ی کارفرما (عناصر بصری) |
| لینک داخلی با «/» پایانی؛ مقصد در سایت یا مخزن | CLAUDE.md |
| مقاله: ≥ ۳ لینک داخلی و دست‌کم یکی به محصول/دسته | خواسته‌ی کارفرما (لینک‌سازی داخلی) |
| FAQ بی‌پاسخ ممنوع | راهنمای Google |
| `sources` الزامی؛ نشان 🔶 در متن ممنوع | قاعده‌ی ۲ |
| «نمایندگی رسمی/مجاز» ممنوع | قاعده‌ی ۳ |
| محصول: brand، categories، gallery | `src/lib/indexability.ts` |

آزمون: `npm run test:content` — هر قاعده روی ورودی خراب قرمز و روی ورودی سالم سبز.

## هم‌نوع‌خواری — قرارداد

- **یک کلیدواژه‌ی اصلی، یک صفحه.** بازبین تکرار را رد می‌کند.
- **صفحه‌ی محصول = نیت خرید** (کدام مدل، مشخصات، سازگاری، سفارش). **مقاله = نیت آموزشی** (نصب، جفت‌کردن، عیب‌یابی). مقاله جدول
  مشخصات کامل را تکرار نمی‌کند؛ یک جمله و لینک به محصول.
- **فرستنده‌ی تنها (مثلاً L12-TX) محصول جداست** با کلیدواژه‌ی خودش («فرستنده ریموت ساگا L12»)، متن خودش و لینک دوطرفه به ست کامل.
  هم‌نوع‌خواری از متن تکراری می‌آید، نه از دو محصول مرتبط.

## مرحله‌ی ۳ — انتشار (ساخته شد، ۲۸ آبان ۱۴۰۵)

1. **افزونه:** اندپوینت `POST /crane-yadak/v1/content` با احراز «رمز برنامه‌ی وردپرس» (Application Password) و قابلیت
   `edit_others_posts`؛ پیش‌فرض dry-run با گزارش تفاوت، `apply: true` برای نوشتن. روی `cyh_hub_import()` ساخته می‌شود و آن را گسترش
   می‌دهد: ساخت محصول/مقاله‌ی تازه (با `create: true` صریح)، عنوان، excerpt، sku، برند، دسته، گالری (با کلید رسانه)، مشخصات.
   ⚠️ قاعده‌ی امروز ابزار ورود «هیچ نوشته‌ای ساخته نمی‌شود» عمداً بود؛ ساختن فقط با پرچم صریح و فقط از این مسیر.
2. **مقاله‌ها بلوکی می‌شوند:** گروه ACF «بلوک‌های محتوا» روی نوع `post` هم فعال و `blog/[slug].astro` با `ContentBlocks` رندر —
   همان سبک برای همه‌ی محتوا (پیش از آن: مهارت `graphql-contract-guard`).
3. **اسکریپت:** تصاویر تازه را با REST وردپرس بارگذاری می‌کند (کلید رسانه از نام فایل، تکراری بارگذاری نمی‌شود)، نشانگرهای
   `{{asset:…}}` را با نشانی واقعی عوض می‌کند، dry-run را نشان می‌دهد و با `--apply` می‌نویسد.
4. **رمز:** کارفرما یک Application Password در وردپرس می‌سازد و در GitHub Secrets / `.env` می‌گذارد؛ دستیار هرگز آن را نمی‌بیند.

## مرحله‌ی ۴ — خودکار کامل (ساخته شد)

GitHub Action روی push به `content/`: lint → publish (dry-run در PR، apply روی main) → Deploy.

## ساخته‌شده — جزئیات و آزمون‌ها (۲۸ آبان ۱۴۰۵)

- افزونه `includes/class-content-api.php`: `POST /crane-yadak/v1/content/import|media|media-meta`، مجوز `edit_others_posts`.
  ۱۷ آزمون هارنس: ساختن فقط با create، dry-run بی نوشتن، **نیمه‌نوشتن ممنوع** (بلوک/گالری/برند/دسته‌ی خراب = هیچ فیلدی نوشته
  نمی‌شود — آزمون همین باگ را در نسخه‌ی اول گرفت)، محتوای دستی و ویرایش پس از انتشار فقط با force، دسته ساخته نمی‌شود،
  تصویر هم‌نام با محتوای دیگر = conflict. چهار جهش عمدی در کد، هر چهار قرمز شد.
- مقاله‌ها بلوکی شدند: گروه ACF روی `post` + `Post` در graphql_types؛ `blog/[slug].astro` با `ContentBlocks`. تا Sync گروه،
  نبود فیلد فقط هشدار build است (برای مقاله، نه برند/محصول/دسته). بررسی معماری حالا نوع‌های هسته (post، page) را می‌شناسد —
  پیش از این با graphql_types غلط سبز می‌شد.
- `scripts/content/publish.mjs` + ۱۵ آزمون با سرور ساختگی: dry-run بارگذاری نمی‌کند، فقط تصویر ناموجود بارگذاری می‌شود، اثر انگشت
  و alt ثبت می‌شود، نشانگر حل‌نشده یا پاسخ ناشناخته‌ی سرور = توقف پیش از نوشتن.
- workflow «Content»: push ← فقط پوشه‌های تغییرکرده؛ فهرست خالی = هیچ (نه همه)؛ force فقط دستی.

## بسته‌ی هر محصول (کارفرما، ۲۹ آبان ۱۴۰۵)

«این فقط برای L12 نیست؛ برای هر محصول همین کار». هر کالای تازه پیش از انتشار این سیاهه را رد می‌کند:

1. **صفحه‌ی محصول کامل** (`content/products/<slug>/`) — نیت خرید، کوتاه.
2. **قطعه‌های جداگانه‌فروش** هر کدام صفحه‌ی خودش (مثال L12: فرستنده، گیرنده) با کلیدواژه‌ی خودش و پیوند دوطرفه به محصول
   کامل. lint تکرار را می‌گیرد: image-dup، cover-dup، text-dup (≥۱۵٪ عبارت ۸ واژه‌ای مشترک).
3. **راهنماها** (`content/articles/`) — هر نیت آموزشی یک مقاله: نصب، جفت کردن/راه‌اندازی، عیب‌یابی، تنظیم/تعویض قطعه.
   مقاله مشخصات را تکرار نمی‌کند؛ پیوند می‌دهد. صفحه‌ی محصول بخش آموزشی را به یک بند + پیوند کوتاه می‌کند.
4. **عکس:** عکس اول هر صفحه یکتا و تمیز (قاعده‌ی ۹)؛ عکس داخل متن کنار بخش مربوط؛ هیچ تصویری دو بار در یک صفحه.
5. **قطعه‌یاب:** SKU یا کد پلاک در محصول ثبت شود تا جستجوی کد پیدایش کند؛ کد ساختگی هرگز.
6. **راهنماهای مرتبط** خودکار است (`src/lib/related-guides.ts`): کافی است مقاله به صفحه‌ی محصول پیوند دهد.
